# 设计说明（1–2 页）

## 一、闭环结构

```
口述目标 ──规则/LLM解析──▶ 结构化目标（+3pp / DSO≤45）
   │
   ├─ 数据契约校验 ─▶ 清洗（3类异常）─▶ 报表口径 + 管理口径基线
   │
   ├─ 诊断：差多少毛利、差多少应收、差在哪个合同/账龄
   │
   ├─ 动作库（毛利/回款）─▶ 穷举组合 ─▶ 基线+保守双情景校验
   │
   ├─ 沙盘执行 ─▶ 失败则剔除动作重规划 ─▶ 回执/账本/日志
   │
   └─ 复核：目标 → 动作贡献 → 预测指标 ─▶ 报告（可复算）
```

核心原则：**数字全部由确定性代码计算，LLM 只做语言理解与摘要**。即使模型不可用，闭环仍能跑完。

## 二、数据清洗

1. **契约校验**：9 列必须齐全；金额可解析、日期 ISO、账期 0-365 天；行数 ≥15、客户 ≥8。
2. **勾稽校验**：当月开票合同满足「应收 = 确认收入 − 实际回款」；退款行满足「成本=0、应收=0、回款=收入（负数）」；合同号唯一；收入不超过合同金额。
3. **异常识别**（只做可解释处置，不静默修数）：
   - 跨期：开票日在期间外但确认了本期收入 → 管理口径冲回收入与匹配成本，保留原值，报告展示两套口径；
   - 退款/折让：红字冲减收入与实际退款 → 保留净额，标记来源；
   - 长账龄：账龄 >180 天 → 不调损益，进入清收队列。
4. **两套口径**：报表口径（9,480,000 元收入、26.69% 毛利率）vs 管理口径（8,520,000 元、25.00%）。清洗让「虚高毛利率」和「看似更低的 DSO」现形，这是后续动作的基线。

## 三、任务拆分

| 阶段 | 模块 | 输入 → 输出 | 失败时 |
| --- | --- | --- | --- |
| 造数/接入 | `data_gen` / `data_io` | 固定种子表 → CSV + 清单 + SHA256 | 缺默认文件→按种子重造；显式路径缺失/坏列→停止 |
| 清洗 | `cleaning` | 原始行 → 异常清单 + 管理口径行 | 契约不满足→exit 2，写失败报告 |
| 指标 | `metrics` | 行 → 收入/成本/毛利/回款/应收/DSO/账龄 | 收入为 0→指标返回 0，不除零 |
| 目标 | `goal` / `llm` | 口述 → +pp / DSO 天 / 目标值 | 规则失败→LLM；仍失败→exit 2 |
| 诊断 | `diagnosis` | 指标 → 缺口金额、低毛利合同、长账龄 | — |
| 动作 | `actions` | 指标 → 带假设/负责人/截止日的动作 | 无候选→不可达报告 |
| 规划 | `planner` | 动作 → 最小可行组合 + 双情景校验 | 无组合→exit 3，输出缺口 |
| 执行 | `execution` | 动作 → 回执 + 幂等账本 | 单动作失败→剔除并重规划 |
| 复核/报告 | `report` / `pipeline` | 全量产物 → 报告 + summary | 未达标→exit 4 |

## 四、动作怎么来、怎么选

- **毛利侧**：从合同成本、成本率、毛利率自动生成——重点供应商降本 7%、高成本率合同降本 4%、最低毛利合同提价 5%（保留 90%）、最高毛利客户追加 5% 订单。
- **回款侧**：对账龄 ≥60 天的应收逐笔生成清收动作，按账龄分档回收率测算，取金额最大 5 笔。
- **选组合**：穷举全部子集，要求同一合同最多一个毛利杠杆（避免降本/提价叠加重复计量），同时满足「毛利率 ≥ 目标 + 0.2pp」「DSO ≤ 45 天」，且所有动作按 95% 实现时仍达标；优先动作数少、保守安全垫大、风险与投入低。演示数据下选出 2 个毛利动作（降本 7% + 降本 4%）和 2 个回款动作（华信 258 天、远达 169 天）。

## 五、指标怎么测、怎么对

- 报告第 2-3 节列出每个指标公式和两套口径；第 5 节给出「Σ动作Δ毛利 = 预测毛利 − 基线毛利」等勾稽表，以及 12 项自动校验。
- 基线：收入 852 万、成本 639 万、毛利 213 万（25.00%）、应收 1,333 万、DSO 48.50 天。
- 计划：毛利 +27.71 万 → 28.25%；回收 117 万 → 应收 1,216 万 → DSO 44.24 天；保守 95% 为 28.09% / 44.46 天，均达标。
- 任意数字都可用原始 CSV 按公式复算；`metrics_before.json`、`plan.json`、`metrics_after.json` 保存中间值。

## 六、失败兜底

| 场景 | 行为 | 证据 |
| --- | --- | --- |
| 默认数据缺失 | 固定种子自动重造，继续运行 | `WARN [ingest]` + 生成目录 |
| 数据损坏/缺列/勾稽不成立 | 不猜测，立即 exit 2，写失败报告 | `report.md` + `events.jsonl` + 行级错误 |
| LLM 不可用/超时/输出非法 | 规则模板摘要，主流程不受影响 | `WARN [narrative]` + `llm_trace.json` |
| LLM 摘要含客户名/新数字 | 拒收并降级 | 数字白名单校验 |
| 动作执行失败 | 剔除失败动作，重新规划并合并回执 | `execution_recovery` + 重规划产物 |
| 目标不可达 | 不执行，输出缺口金额/天数，exit 3 | 报告第 5 节 + `summary.json` |
| 未预期异常 | 记录 traceback，exit 5，保留现场 | `events.jsonl` |

演示命令：`--chaos llm-down`（模型不可用）、`--chaos action-fail`（动作失败后恢复）、`--chaos data-corrupt`（坏数据 exit 2）。

## 七、边界

- 原型验证的是「目标→动作→指标」的闭环逻辑和工程兜底，不是生产级财务系统；执行是沙盘模拟，不写真实系统。
- DSO 单月近似、动作效果为管理假设，真实上线需滚动口径、权限、审批与回填机制。
- 模型只处理聚合摘要；真实财务数据应使用私有化部署（Ollama/vLLM）并做脱敏与访问审计。
