# 模型选型与接入说明

## 选择

**首选：DeepSeek-V3（国产 API，`deepseek-chat`）。**
**私有化备选：Ollama / vLLM 部署 Qwen2.5-7B-Instruct（OpenAI 兼容端点）。**

## 为什么

| 维度 | 说明 |
| --- | --- |
| 中文经营语境 | 老板口述、财务口径、动作表述都是中文，DeepSeek 的中文理解与生成质量足够，API 成本低。 |
| 合规与数据边界 | 国产 API 数据不出境；若客户要求完全私有化，同一客户端只需把 `LLM_BASE_URL` 指向内网 Ollama/vLLM，不改业务代码。 |
| 接口通用 | OpenAI 兼容的 `/chat/completions`，DeepSeek、Qwen、智谱等都可切换；不绑定单一厂商 SDK。 |
| 工程可控 | 只让模型做「目标解析兜底 + 3 条摘要」，金额、指标、动作测算全部由本地确定性引擎计算，模型故障不影响闭环。 |
| 可验证 | 摘要中每个数字都要能在事实包里找到，否则拒收并降级；提示词要求不出现客户名称。 |

## 模型在系统里做什么

1. **目标解析兜底**：规则解析失败时，把口述解析为 `{"margin_delta_pp": 3, "dso_target_days": 45}`；基线换算、范围校验仍由代码完成。
2. **经营摘要**：根据匿名事实包（基线/目标/预测/动作数/异常类数）生成 3 条中文要点，写入报告第 7 节。

模型**不**参与：收入确认、清洗、指标计算、动作金额、组合搜索、目标达成判断。这样即使模型幻觉，也不会改数。

## 接入方式

```bash
# 国产 API（默认）
export DEEPSEEK_API_KEY=sk-...
python -m bizgoal llm-check
python -m bizgoal run --out runs/with-llm

# 私有化：Ollama（示例）
ollama pull qwen2.5:7b-instruct
export LLM_PROVIDER=ollama
export LLM_BASE_URL=http://127.0.0.1:11434/v1
export LLM_MODEL=qwen2.5:7b-instruct
python -m bizgoal llm-check
```

| 环境变量 | 默认 | 说明 |
| --- | --- | --- |
| `LLM_PROVIDER` | `deepseek` | `deepseek` / `ollama` / `openai-compatible` |
| `LLM_BASE_URL` | 按 provider | OpenAI 兼容根地址，末尾不要带 `/chat/completions` |
| `LLM_MODEL` | `deepseek-chat` | 模型名 |
| `LLM_API_KEY` / `DEEPSEEK_API_KEY` | 空 | 私有化 Ollama 可不填 |
| `LLM_TIMEOUT_SECONDS` | 25 | 单次超时 |
| `LLM_MAX_RETRIES` | 1 | 重试次数 |
| `LLM_ENABLED` | 未设置 | 设为 `off` 可强制关闭 |

## 当前交付环境的真实状态

本交付环境未注入任何模型密钥，也没有本地模型服务。因此：

- 正常演示走**规则解析 + 规则模板摘要**，报告会如实写「未调用（未配置 DEEPSEEK_API_KEY / LLM_API_KEY）」；
- `--chaos llm-down` 模拟模型服务不可用，验证降级路径仍能跑完并留日志；
- 用上面的 `DEEPSEEK_API_KEY` 或 Ollama 配置重跑，同一个命令即可让第 7 节变成模型摘要；`llm-check` 会返回连通性、延迟和模型名；
- 这不是把模型当摆设：客户端、JSON 解析、数字白名单校验、超时/重试/降级、trace 都已实现并有单测（本地 mock HTTP 服务验证成功、幻觉拒收、不可达降级）。

## 成本与风险

- DeepSeek 每次运行只调用 1-2 次（目标兜底 + 摘要），输入为几百 token 的聚合事实，成本可忽略。
- 主要风险是幻觉与合规：已用「数字白名单 + 不发送客户名 + 不参与计算」控制；真实数据上线前应做数据分级、审计日志、私有化部署。
- 不把模型输出当作审批依据；最终数字以确定性引擎和回填的实际值为准。
